# Implementation Plan: Admin Direct Write & Sync Removal

## 1. Objective
Modernize the Admin Panel UX by removing the "Push Changes" / "Syncing" manual step. The interface will transition to a "Live Edit" model where every action (Approval, Pot Adjustment, Deadline Change) is immediately committed to the data source (Mock Database) and reflected instantly in the UI.

## 2. Targeted Component
- **File:** `pages/Admin.tsx`

## 3. Structural Changes

### A. Remove the "Push Sync" Mechanism
1.  **Delete UI:** Remove the "Push Updates" / "Syncing..." button from the top header action bar.
2.  **Delete State:** Remove the `isSyncing` state variable.
3.  **Delete Logic:** Remove the `handlePushChanges` function entirely.

### B. Refactor Action Handlers (The "Direct Write" Simulation)
In the current Mock environment, "Direct Database Write" means mutating the Global Constants (`MOCK_LEAGUES`, `MOCK_MEMBERS`) and *immediately* refreshing the local React state to reflect that change.

**Handler Audit & Update:**

1.  **`handleApprove` & `handleReject`:**
    - Current: Mutates `MOCK_MEMBERS` -> Calls `setMembers`.
    - Action: Ensure these operations happen synchronously. Add a `window.alert` or Toast notification (optional) or simply rely on the visual state change (row disappears/moves) as confirmation.

2.  **`handleDeadlineUpdate`:**
    - Current: Mutates `MOCK_LEAGUES` -> Calls `setLeagues`.
    - Action: This is already "Direct". Ensure the `<select>` value updates instantly.

3.  **`handlePotUpdate` (Financials):**
    - Current: Updates on `onBlur`.
    - Action: Keep `onBlur` to prevent jitter while typing, but ensure the `setLeagues([...MOCK_LEAGUES])` trigger runs immediately after the mutation.

4.  **`handleManualOverride` (Toggle):**
    - Current: Mutates `MOCK_LEAGUES` -> Calls `setLeagues`.
    - Action: Immediate toggle.

## 4. Visual Feedback (UX)
Since we are removing the "Save" button, we need to ensure the user knows their action worked.

- **Status Badges:** When a user is approved, the list should strictly re-render immediately.
- **Toggle Switches:** Should snap instantly.
- **Input Fields:** The "Pot Management" input currently uses `defaultValue`. To ensure "Live" feel, we might want to ensure the displayed value in the emerald card updates instantly upon `onBlur`.

## 5. Verification Checklist
1.  **Click Test:** Click "Approve" on a pending user.
2.  **Expectation:** The user vanishes from "Pending" and appears in "Points Control" *instantly* without clicking any other button.
3.  **Persistence Test:** Navigate away to "Leagues" and come back. The change must persist (it will, because we modified the `MOCK` constants).
4.  **Cleanliness:** Ensure no "Syncing..." spinners or buttons remain in the DOM.

## 6. Future-Proofing (Preparation for Firebase)
This architecture aligns perfectly with Firebase. Later, we will simply replace:
`MOCK_MEMBERS[i].status = 'approved'`
with
`await updateDoc(doc(db, 'members', id), { status: 'approved' })`
...and the UI behavior will remain exactly the same (Instant/Optimistic).
