# MASTER PLAN: Firebase Production Migration & Real-Time Sync

## 1. Executive Summary
**Objective:** Convert the current React application from using local mock data (`constants.ts`) to a live Firebase backend (Authentication + Firestore Database).
**Core Requirement:** The Admin Panel and User Website must be perfectly synchronized. Actions taken by an Admin (e.g., "Approve Member", "Update Pot", "Change Deadline") must propagate to connected User Dashboards in real-time via Firestore listeners.
**Deployment:** The final output must be a single deployed URL (SPA) handling both Admin and User routes, secured by Firebase Hosting.

---

## 2. Configuration & Authentication
**Action:** Create `lib/firebase.ts`.
1.  Initialize Firebase App with environment variables.
2.  Export `auth` and `db` (Firestore) instances.
3.  **Authentication Refactor:**
    - Replace `CURRENT_USER_ID` constant with `useAuthState` hook from `react-firebase-hooks/auth`.

The agent must structure the NoSQL database exactly as follows to ensure the logic works:

### Collection: `users`
- `uid` (string): Auth ID
- `email` (string)
- `display_name` (string)
- `role` (string): 'user' | 'league-admin'

### Collection: `leagues`
- `id` (auto-id)

### Collection: `members`
- `id` (auto-id)
- `league_id` (string)
- `user_id` (string)
- `status` (string): 'pending' | 'approved' | 'rejected'
- `joined_at` (timestamp)
- `points` (number)

### Collection: `weeks`
- `id` (auto-id)
- `league_id` (string)
- `week_number` (number)

### Collection: `picks`
- `id` (auto-id)

## 4. The "Perfect Sync" Strategy (React Hooks)
To ensure Admin actions reflect immediately on the User Website, the agent MUST NOT use `getDocs` (one-time fetch). 
The agent **MUST** implement custom hooks using `onSnapshot`.

**Create file: `hooks/useSyndicateData.ts`**
1.  `useLeagues()`: Returns `leagues[]`. Listens to `collection(db, 'leagues')`.
2.  `useLeagueMembers(leagueId)`: Listens to `members` where `league_id == leagueId`.
3.  `useActiveWeek(leagueId)`: Listens to `weeks` where `league_id == leagueId`.
4.  `useWeekPicks(weekId)`: Listens to `picks` where `week_id == weekId`.

*Effect:* When Admin updates a doc in `leagues`, `useLeagues()` triggers a re-render in `Dashboard.tsx` instantly.

---

## 5. Admin Panel Refactor (`pages/Admin.tsx`)
**Replace all Mock Mutations with Firestore Write Operations:**

1.  **Create League:** `addDoc(collection(db, 'leagues'), { ...data })`.
    - *Auto-Action:* Immediately create a "Week 1" doc in `weeks` collection for this new league.
2.  **Approve Member:** `updateDoc(doc(db, 'members', memberID), { status: 'approved' })`.
    - *Sync Check:* Triggers Week 1 `pick_order` recalculation if Week 1 is 'upcoming'.
3.  **Update Pot:** `updateDoc(doc(db, 'leagues', leagueID), { current_pot_pence: newValue })`.
4.  **Update Deadline:** `updateDoc(doc(db, 'leagues', leagueID), { pick_deadline_day: d, pick_deadline_hour: h })`.
5.  **Generate Next Week:**
    - Transactional write: Close current week doc + Create new week doc with rotated `pick_order`.

---

## 6. User Dashboard Refactor (`pages/Dashboard.tsx`)
**Replace Mock Reads with Hook Data:**

1.  **Gatekeeping:** Use `useLeagueMembers`. If `currentUser.uid` is not found or status is 'pending', show "Access Restricted" (The component will auto-update when Admin clicks approve because of the listener).
2.  **Draft Room:** Connect `DraftRoom.tsx` to `useActiveWeek` and `useWeekPicks`.
    - *Real-time Draft:* When User A makes a pick, `current_turn_user_id` updates in Firestore. `DraftRoom` on User B's screen sees the change instantly via `onSnapshot` and unlocks their turn.
3.  **Pick Submission:**
    - Run inside a Firestore Transaction:
        1. Check if `week.current_turn_user_id === currentUser.uid`.
        2. Create/Update `picks` doc.
        3. Update `weeks` doc (`current_turn_user_id` -> next user).

---

## 7. Security Rules (firestore.rules)
**Strict enforcement to prevent console hacking:**
1.  `leagues`: Read: All. Write: Admin Only.
2.  `members`: Read: Member of league. Write: Admin Only (except 'create' for joining).
3.  `weeks`: Read: Member of league. Write: Admin Only.
4.  `picks`: Read: Member of league. Write: Owner of pick AND it must be their turn.

---

## 8. Deployment Steps
1.  Run `npm run build`.
2.  Initialize `firebase init hosting`.
3.  Set build folder to `dist` (or `build` depending on Vite config).
4.  Configure as SPA (Rewrite all urls to `/index.html`).
5.  Run `firebase deploy`.

**Output:** Provide the Hosting URL.
